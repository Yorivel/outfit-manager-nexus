# Changelog

Outfit Manager for Crimson Desert. Downloads: [Nexus Mods](https://www.nexusmods.com/crimsondesert/mods/4029) or this repository's [releases](https://github.com/Yorivel/outfit-manager-nexus/releases).

## Unreleased

- Fix: the helmet in Kliff's hand during the helmet animations keeps its dye. It showed its original colours until it was back on his head; the same went for a worn Visione.
- Fix: viewing a memory while wearing a hidden Visione now looks the same as without one: Kliff takes the Visione on, the memory plays, and he takes it off again. The game plays no take-on when the Visione is already worn (Kliff only touches it), so Outfit Manager kept it hidden; it now plays the helmet animations itself, following the Visione's own effect, which switches on for the memory and off once it ends. Your helmet's visibility setting stays as it is. On a mount it simply shows for the memory. In a very short memory the Visione can appear only near its end: the take-on takes about three seconds (#57).
- Technical: the hand prop the game draws comes from a Visione it looks up in the bag. With the worn helmet's info that lookup searched for the helmet, found nothing and built an undyed one; it now searches with the Visione's own info, and the item it gets is the worn helmet (when the bag holds no Visione, the lookup is answered as found and the worn helmet is handed over all the same). The game's other prop, never seen, is left alone: made the helmet too, its shadow fell on his face. New addresses: the bag lookup and the prop build's call site (the item at a bag index was already known), both in the resolver (2 new recipes; the call site's pattern holds both calls where they're expected - moved apart: not found, the dye fix is off). Backtested on every older build: no wrong address (before 2.05 the call site isn't found). The worn Visione's use: an EffectSwitch from the gimmick docked to him naming the Visione's state 0x31B02410 (gimmick_equip_visione) starts it; the same gimmick's 0x150B14D0 ends it. Outfit Manager's take-on starts at the first, its take-off at the second; the Visione shows from the take-on's moment the hand has it on until the take-off's moment it lifts it.

## 0.8.3 (2026-11-19)

- Works on the game update of 2026-11-19 (1.0.0.3732): every game address found again and checked; the game's code that Outfit Manager calls is unchanged apart from two internals that don't affect it.
- Fix: the Outfit Arc's Helmet entry (controllers, 0.8.2) is translated: it showed "Hide Helmet" / "Show Helmet" in English in every language.
- Fix: Character Look on a character who has never been to a barber (Oongka, until his first visit) said "your character's look couldn't be read". The game gives a character a barber look only at their first visit, so there is nothing to read until then; it now says so ("This character has no barber look yet: visit a barber once, then take the snapshot"), and Outfit Manager stops trying to read it every second for half a minute after each outfit change.
- Fix: on the game update of 2026-11-19 (1.0.0.3732) the outfit effect's particle budget wasn't found at start-up, so busy scenes could flicker while a glow played. Outfit Manager now checks the value when a glow starts instead of at start-up (the game sets it later), and searches once more at the first glow if the search at start-up found nothing.

Its name says what it does now, Hide Helmet or Show Helmet; its icon is the game's empty helmet slot. With mouse and keyboard there's no such entry: the helmet key does it. Thanks for the idea, Youseff2204!
- Fix: a save the game made right as you hid or showed your helmet kept the helmet as it was before.
- Fix: with a PlayStation controller, the Outfit Arc (L1 + down) only opened after the outfits menu had been opened once.

It now follows the game's own loading state.
- Fix: loading another save no longer gives your character the previous save's look (hairstyle, beard...) when the loaded save has none of its own stored, or a different one. Outfit Manager applied the look before switching to the loaded save's outfits.
- New: a Swimming activity (#54). Set an outfit's Activity to Swimming and it goes on when you get into the water (with several, one at random); what you wore before comes back once you're back on dry land - standing, walking or running on ground, a boat's deck or a dock, or running across the water with the WaterMove skill (that counts as land). Jumping out of the water, falling, gliding or the rocket pack change nothing, so jumping out and dropping back in keeps your swimwear on. Combat and Sleeping win over it: after a fight your swimwear comes back if you're still in the water, and if you reached land meanwhile, what you wore before the swim comes back instead. An outfit you put on yourself during a swim stays (nothing is swapped back later). Its badge is the game's wave. Thanks for the idea, keksdieb101!
- Technical: where the played character's lower body is, from his lower-body action chart layer's states seen at the branch evaluator (the flight hook) for his own chart (its actor's id): in the water = one of basic_lower_swim / basic_lower_underwater's 83 states (swim_states.inc); on ground = one of 284 ground states (ground_states.inc: basic_lower's 230 and basic_lower_crouch's 54 - all but the jumps, falls, landings, glides, climbing, wall runs, slides and dodges, and the wading in the shallows, so the swim ends on dry land; the WaterMove skill's five surface-run states, skill 10265 Skill_WaterMove_Enhanced, count as ground, never as water); any other state changes nothing. Game 2.05's charts, shared by the three player characters. A swim starts in the water and ends on the first ground state after it; a save loaded drops its state. The game's wet buffs aren't used: they all end the instant he leaves the water (tested 2026-11-18), so no recipes or offsets of its own - Swimming needs only the evaluator hook.
- New: loading a weapon set also picks the weapon its icon shows, as picking it in the game's weapons tab does - a set with your woodcutter's axe or pickaxe as its icon puts that tool in your hands, no trip to the weapons tab (#53). The icon's weapon is the one the set's Icon setting chose, else its main-hand weapon, else its first weapon; loading a set you already wear picks it too. When that weapon isn't worn after the load, or isn't one the game lets you pick (or the game refuses), a message says so. Thanks for the idea, FF7Seph!
- Technical: the weapons tab's click on a slot showing its worn piece calls the inventory's change function (bag 0xFFFF, the equip slot); for a hand weapon (its equip type's flag) outside the weapon group in hand it sends TrocTrReserveToChangeEquipFromQuickSlotReq and the character changes weapons (ChangeEquipByQuickSlot), which OM now does the same way once a set's load is done. A piece in the group in hand is left alone (there the game would run the item's own actions instead). 3 new recipes (the change function, the equip type getter, a weapon group's slots) and 3 offsets (an item's equip type +4A, the type's hand-weapon flag +F, the group in hand +B0); any of them not found or unsure: no weapon is picked. Backtested on every older build: no wrong address or offset (before 2.05 the equip type getter took its key by value and isn't found, and the offsets aren't witnessed: off there).
- Changed: a weapon set's badge now shows what kind of set it is, from the weapon its picture shows: crossed swords for melee, a bow for ranged weapons (bows, crossbows, guns, cannons), and an axe for tools (axes and pickaxes for gathering, saws, brooms, fishing rods, lanterns...). Still gold while the set is equipped and pulsing while it loads.

## 0.3.3 (2026-11-05)

- Compatibility: works alongside other mods that change the gear wheel, in any load order. Tested with Better Radial Menus: both mods now apply in full, with no conflict in DMM.
- The mod no longer ships any of the game's own files. Until 0.3.2 it replaced four compiled gear-wheel UI files (ui/bin__/*.uibinary) and the wheel's texture list (cd_hud_itemquickslot_08.xml) as whole files. DMM keeps only one mod's copy of a whole file, so whichever mod lost the conflict lost its changes: with Outfit Manager losing, the Outfits tab disappeared.
- Technical: the plugin now hooks the game's UI loader where it hands a compiled UI file to its parser (pattern-scanned, not a fixed address). The hook goes in while the plugin itself loads, before the game builds any screen, so nothing depends on timing.
- Technical: when one of the three gear-wheel files comes through (itemquickslotview2_game, its _component file, quickslotitem_component_game), the plugin copies whatever version DMM chose (the game's or another mod's) and inserts the Outfits tab header (a copy of the last tab header, QuickSlotHeader8) and the gold value text (a copy of each slot's CoolTimeChargedCount text). The parser gets the patched copy. On the game's own files the result is byte for byte what 0.3.2 shipped.
- Technical: if a file isn't laid out as expected (say, an update renames those elements), it is left untouched and the log says why. The gear wheel then works as normal, just without the Outfits tab, instead of breaking. Every patched file is logged ("gear wheel UI: ... added") so a bug report shows which copy was patched.
- Technical: the texture list entries now come only from the XML merge, which DMM adds onto whatever copy of the list it mounts. The quickslotitem.thtml merge is gone: since the 10-30 patch the game builds its screens from the compiled .uibinary files and never reads .thtml.
- Game updates that change the gear-wheel files no longer need a new version of the mod, as long as the two elements it copies are still there.
- Update resilience: seven more fields the plugin reads from the game are now checked against the game's own code at start-up and followed if a patch moves them: the name box's caret, selection end, caret-redraw flag, busy flag and text element (typing symbols), an element's on-screen rectangle (controller aiming, button prompts) and the dots-per-page field (slot dots). That makes 57 fields and 129 code addresses, all found again by search after an update.
